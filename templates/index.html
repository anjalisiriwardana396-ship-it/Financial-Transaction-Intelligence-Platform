What is a Behavioral Profile?

The system analyzes each customer's spending history to establish a baseline of normal activity. From this baseline, it derives behavioral features including transaction frequency, average spending and deviation thresholds, merchant category preferences, peak transaction hours, geographic concentration, and velocity patterns. These features are combined with transaction-level details and fed into the fraud detection model to provide contextually aware risk scores.

How Behavioral Features Improve Fraud Detection When a new transaction arrives, the system compares it against this behavioral baseline. A $1,200 transaction at 2am via Online method would score highly suspicious because: (1) $1,200 is above the — high-spend threshold, (2) 2am falls in the —% unusual hours category, and (3) Online transactions carry a 1.14% fraud rate in this dataset. These contextual flags appear alongside every model prediction.

Recommendations

Prioritise fraud monitoring on Online transactions. With a 1.14% fraud rate — approximately 28× higher than Chip — card-not-present payments represent the highest risk channel.

Implement time-based fraud alerts. SHAP analysis identifies transaction hour as the second most influential predictor. Transactions at 2am–5am show elevated risk profiles.

Use behavioral deviation scores alongside model predictions. A transaction 3 standard deviations above a customer's personal spending baseline should trigger additional verification.

Use ROC-AUC as the primary evaluation metric. With 0.135% fraud cases, a model predicting "no fraud" achieves 99.9% accuracy but catches zero actual fraud.

Risk Detection

Severe class imbalance: only 27 fraud cases out of 19,963 (0.135%). Recall of 0.20 means 80% of actual fraud in the test set was missed even after SMOTE balancing.

Hour 6 anomaly detected: over 9,255 transactions (~46%) are timestamped at exactly 06:00, representing $875K in spending. Almost certainly a data quality issue with missing timestamps.

Single-user dataset: all 19,963 transactions belong to one cardholder. Models should not be deployed without retraining on diverse multi-user data.

Transaction amount is a weak signal (SHAP rank 7 of 8). Behavioral deviation scores provide the missing context for amount-based fraud detection.

Project Narrative

The project first analyzes each customer's spending history to establish a baseline of normal activity. From this baseline, it derives behavioral features including transaction frequency, spending statistics, merchant preferences, peak transaction hours, geographic concentration, and velocity patterns. These behavioral features are combined with transaction-level details and fed into the fraud detection model. Each prediction includes behavioral context flags comparing the transaction against the customer's baseline — a context-enhanced fraud risk score, not just a binary prediction.

Why ROC-AUC and not Accuracy A model predicting "no fraud" always achieves ~99.9% accuracy but catches zero fraud. ROC-AUC measures ranking ability regardless of class distribution — the correct metric here.
Probability Calibration Probability calibration was not performed due to limited fraud samples. Scores should be interpreted as relative risk rankings rather than calibrated real-world probabilities.
Why Random Forest was selected Random Forest was selected based on the best overall balance between ROC-AUC, precision, and fraud detection capability. Although Logistic Regression achieved higher recall, it produced significantly lower precision and more false positives.

About This Project

An end-to-end financial transaction intelligence system built on 19,963 credit card transactions spanning 18 years (2002–2020). The system analyzes customer spending behavior, builds behavioral baselines, identifies potentially fraudulent transactions with contextual explanations, and provides interactive analytics via a live web dashboard.

1

Data Cleaning

Removed $ signs, combined date columns, filled 21K+ missing values. Added DayOfWeek, Hour, FestivePeriod, and Category columns.

2

Feature Engineering

Extracted Hour from Time column. Mapped 15 MCC codes to readable categories. Engineered custom period groupings: Avurudu, Christmas, New Year, Valentine, Normal.

3

Behavioral Profile

Built 8 behavioral features including transaction frequency, spending statistics, amount deviation thresholds, merchant preferences, time profile, geographic concentration, velocity patterns, and historical fraud patterns.

4

Imbalance Handling

Applied SMOTE after train/test split. Training set balanced from 22 to 15,948 synthetic fraud examples. Test set kept original and unmodified.

5

Model Training

Trained Logistic Regression, Random Forest, and XGBoost. Random Forest selected on ROC-AUC 0.98. Each prediction includes behavioral context flags.

6

SHAP Explainability

TreeExplainer applied on a representative sample of 200 transactions.

7

Flask Deployment

13 API routes serving predictions, behavioral profiles, chart data, KPIs, exports, and comparison data. Interactive dashboard with 9 pages.
